# AskPIP Core Changelog

This changelog records significant changes to AskPIP Core in a concise, human-readable form.

Git provides the complete technical history of the repository. This changelog records the major documents, decisions, releases and structural changes that are important to the Founders and future contributors.

---

## Unreleased

### Added

- Fixed a real usability gap in the Garden Shed's desk windowing, found immediately after the full-screen/cycle buttons shipped (9 September 2026): expanding — and especially maximizing — a document could leave any other, still-minimized window entirely hidden behind it, with no way left to reach it. Reproduced first with a headless-browser test of the exact reported case (a maximized document, its notice still closed) before fixing, and again after. `layoutDeskWindows` now reserves a strip along the right edge whenever a minimized card shares the desk with an expanded window, and pushes every expanded window's edge (and shrinks its width) to stay clear of it — so a closed document or notice always keeps a visible, clickable corner "out the side," per the Founder's own suggested fix, rather than disappearing. Skipped below the shed's 700px mobile/desktop breakpoint, where there's no width to spare. Also fixed a related latent bug this surfaced: the card→panel "Expand" button never called the layout function at all. See `Shed/README.md` for the full technical record.
- Extended the Garden Shed's notice/approval workflow a second time (9 September 2026, same day as the review-request extension below), plus two general desk-window improvements requested at the same time. Five pieces: (1) **Auto-created to-do on every approval-required notice** — a new database trigger (`shed_notice_auto_todo_trigger` migration) fires on every `shed_items` insert with `requires_approval = true` and creates the matching `shed_todos`/`shed_todo_status_log` rows automatically, replacing the manual step previously needed for each new notice. (2) **Notice Board hotspot badge** — a live pending-notice count now shows on the Notice Board hotspot itself, on both mobile and desktop. (3) **Document-side pending-notice indicator** — a document with a pending notice against it now shows a "⚑ Pending" badge in list views and a "⚑ N approval notice(s) pending" button in its own desk panel, linking straight to the notice. (4) **Unmistakable approval feedback** — approving or requesting review now gives the approval-status line a distinct colour per state (grey/pending, green/approved, terracotta/review-requested) and a brief flash on every save, after a report that Request Review appeared to "do nothing" turned out to be a pure feedback-visibility problem (the RPC had worked correctly — confirmed by a direct database check). (5) **Full-screen expand and cross-panel cycle buttons** — every expanded desk window now has a full-screen toggle (⤢) for easier reading, and, when more than one panel is open, a cycle button (⇄) to jump between them without minimizing first. See `Shed/README.md` for the full technical record.
- Extended the Garden Shed's notice/approval workflow with a review-request path and simplified how items are browsed (9 September 2026, same day as the workflow's initial build). Three pieces: (1) **Review requests** — a notice's approval checkbox and notes now sit alongside a "Request Review" action (`shed_request_notice_review` RPC; `review_requested`/`review_requested_by`/`review_requested_at` columns on `shed_items`), so a reviewer can flag requests, changes or disagreements instead of approving outright; approving clears a pending review request and vice versa, so a notice is always in exactly one of three states. (2) **Notices now show a live subtitle and creation date** — the linked document's title renders under the notice's own title (computed live from `linked_item_id`, so it can't go stale), followed by "Created ..." and the notice's own text under a "Things to be aware of" heading; the minimized card shows "Re: <document>" instead of a generic snippet. (3) **List views simplified**: the Notice Board, File Cabinet and Bookshelf now show only a title and a "Send to Desktop" button — no inline preview, no Edit/Delete there — per the Founder's direction that viewing and editing should happen only in a desk window, never in the list itself. See `Shed/README.md` for the full technical record.
- Created the shed's first Founder-approval notice (9 September 2026): "Founder Approval Required" on the Notice Board, linked to `Foundations/Founding_Principles.md` (the oldest and most foundational of the four still-unapproved Foundation documents — original draft 15 July 2026, predating the other three), with a matching To-Do List task. Not yet approved.
- Rebuilt the Garden Shed's desk, File Cabinet and notice workflow around a Founder-approval process for Core drafts (9 September 2026), per the Founders' direction that the shed's File Cabinet should mirror Core's own document tree and that approving a document should happen from the shed itself. Four pieces: (1) **Document sync scope expanded** from three folders (`Foundations/`, `Knowledge Curation System/`, `Standards/`) to the whole documentation surface — `MVP/`, `Working/` and `AI/` and `Graphics/` added — with each synced item's `folder` now holding its full relative directory path rather than just a top-level name, so the shed can present real nested subfolders. (2) **File Cabinet rebuilt as a nested tree browser** matching Core's actual folder structure, using two new helpers (`cabinetChildFolders`/`cabinetItemsAt`) shared with the new document-link picker. (3) **The desk rebuilt as a multi-window, staggered, click-to-front stack** — unlimited windows, each minimized (card) or expanded (panel), so a notice and the document it concerns can be open side by side, replacing the old single-item full-screen overlay. (4) **Notice/approval workflow added**: a notice can require approval and link to a specific document (`shed_add_notice`, `shed_set_notice_approval` RPCs; `linked_item_id`/`requires_approval`/`approved`/`approved_by`/`approved_at`/`notes` columns on `shed_items`, all additive — no existing RPC signature changed). Approval is deliberately a shed-side record only — it does not write back to the Core document or to git, which stays a separate manual step — but is retrievable directly from `shed_items` by any AI session working in this repo, a hard requirement from the Founder. Images/binary files remain out of scope for sync, per the Founder's explicit "documents first" phasing decision; real image support is a follow-up phase. See `Shed/README.md` for the full technical record.
