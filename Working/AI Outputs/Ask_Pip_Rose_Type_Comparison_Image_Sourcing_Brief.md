## 1. Why this document exists, and what it is not

`FRD-BUSHROSE-ROSETYPE-01` and `FRD-BUSHROSE-ROSETYPE-LABELS-01` researched how rose types are described and labelled, but neither supplies an image — `ROSETYPE-01` §7 explicitly calls a comparison-image list "production work drawn from approved findings and not a finding of this commission." `Photo_and_Comparison_Image_Requirements_Rose_Types.md` did that production work: for each of the three in-scope types (Hybrid Tea, Floribunda, Grandiflora) and eight excluded lookalikes (Shrub, Patio, Miniature, Miniflora, Groundcover, Climbing, Standard, Old Garden/species), it states what a photo must show, how it needs to be framed, and what the evidence says a photo cannot settle.

This Brief takes that requirements document one step further, the same way the original Comparison Image Sourcing Brief operationalised the six diagnostic observations: it assigns a Tag ID and tracks Image Status for each of the eleven images, records that all eleven have already been generated as AI placeholders and added to the Shed gallery, and gives the exact title and notes text each gallery entry needs so the gallery stays legible — matching §11.5 of the original Sourcing Brief.

**What this document does not do.** It does not decide whether Grandiflora stays in scope, whether patio roses stay excluded, or any other question reserved to Founder Decision Points in either ROSETYPE dossier. It does not source, photograph or license a single real image — every image referenced here is an AI-generated placeholder. And it does not populate the eventual qualifying-questionnaire content or the "supported rose type" Suitability Gate itself (Architecture §5.4) — that remains separate, downstream work once an ARC exists.

## 2. Cross-cutting requirements — read before sourcing anything

**AI-generated placeholder images are permitted for internal app-function testing only**, on the same terms as the original Sourcing Brief §2 (Shaphan, exercising Founder Authority under Asset Lifecycle Standard §3.3, extended to this image set 28 September 2026): each image must accurately match its entry's stated Feature Demonstrated and Viewpoint/Scale/Context fields below, drawing on the same research base as `Photo_and_Comparison_Image_Requirements_Rose_Types.md`; must carry a Tag ID and be recorded with Image Status `Placeholder — AI-generated`; must never be marked `Approved`, and must never be represented to a gardener as a real photograph; and must be replaced with a genuinely sourced or photographed image, and re-reviewed, before any gardener-facing or production use.

**Image rights are an open problem here too, exactly as for the six observations.** No image below has been requested, acquired or approved from any real-world source. Nothing here can be filled by screenshotting a cited retailer's or society's own photograph — every real reference image still needs to be newly photographed or sourced from a collection with confirmed reuse rights.

**Retail terminology should not be used as a substitute for a real photograph.** Both ROSETYPE dossiers found that words like "bush rose" are used inconsistently at retail in every market checked — a comparison image exists precisely to give Pip (and a gardener) something more reliable than a retail label alone, per `FRD-BUSHROSE-ROSETYPE-LABELS-01` AF-26.

**Dormancy is not addressed by this image set.** Every entry below assumes an actively growing or flowering plant. No source in either ROSETYPE dossier addresses what any of these eleven types look like leafless and dormant — a separate Founder decision, tracked as Recommendation R-1 in `FRD-BUSHROSE-ROSETYPE-01`, governs what (if anything) Pip does with a dormant-season photo.

## 3. How to read each entry

Each entry below is structured the same way as the original Sourcing Brief's entries (PKR Standard §5.2 fields, adapted for a type-recognition rather than a diagnostic-observation image):

- **Feature Demonstrated** — the specific, evidence-grounded feature the image exists to show, drawn directly from an Assessed Finding in one of the two ROSETYPE dossiers (cited by AF number).
- **Viewpoint, Scale and Visible Context** — how the image needs to be framed.
- **Common Lookalikes / Cross-references** — which other type in this same set it's most likely to be confused with.
- **Limitations** — what this image cannot establish on its own, per the underlying research.
- **Image Source, Verification Status, Approval Status** — filled in below; all eleven are currently AI-generated placeholders, none Approved.
- **Accessible Label** — a plain-language draft.
