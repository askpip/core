# Live Intelligence Library (LIL)

This folder is the repository side of the LIL: every PIP Knowledge Record (PKR) that has entered the LIL, in the exact form Pip reads it. The live LIL is the Supabase table `public.lil_pkr` (project `lapscltduzkbldfwcemq`). The two are kept identical by KIT's build tool and verified by hash after every publish.

Custodian: the Knowledge Integration Technician (KIT). Procedure: `AI/Skills/KIT_LIL_Publication_Skill.md`. Governing documents: LIL Standard, PKR Standard, KIT Operations Manual.

## What is here

| Path | What it is | Edited by |
|---|---|---|
| `records/PKR-XXX-NNNNNN/vX.Y.json` | One file per PKR version (schema `pip-lil-record/1`). A published version file is never edited; a change is a new version file. | KIT |
| `lil_bundle.json` | Every record in one file. The database reads it at a pinned commit. | Generated |
| `lil_manifest.json` | Every record's ID, version, status and content hash: what the live LIL must contain. | Generated |
| `tools/build_lil.py` | Validates records and generates the bundle, manifest, app snapshot and SQL. Python standard library only. | KIT (as software) |
| `tools/lil_schema.sql` | The database schema: table, Row Level Security and the `lil_publish_from_git` function. | KIT (as software) |
| `build/` | Generated SQL, not committed. | Generated |

The app's offline copy, `App/src/data/lil-snapshot.json`, is also generated by `build_lil.py`.

## Why a database, with this folder as its mirror

Decided on 1 October 2026. The Founders left the choice to the implementer, asking only that it scale as the library grows.

- **Scale.** A database table with indexes keeps retrieval fast at any size. The app can load only what it needs (by record type, or by plant scope later), never the whole library.
- **Safety.** The app can read Published rows only and can't write at all (Row Level Security). Only KIT's publish function writes.
- **Reach.** A newly published or corrected record reaches gardeners without an app release.
- **Traceability.** Every record is also a reviewed file in git. Each publish is pinned to a git commit, recorded in `public.lil_publish_log`, and checked by content hash.

## Record status

The LIL holds only records that have entered it:

- **Published** (Pip uses it; at most one version per PKR);
- **Suspended** (withdrawn by Founder direction under review);
- **Retired** (superseded or withdrawn; kept for traceability).

Drafts never enter the LIL. They live in `Working/AI Outputs/` as submission packages until the Founders approve them.
